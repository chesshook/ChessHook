# ChessHook Stockfish API

The API runs inside the GitHub Codespace on TCP port `8765`. The server binds to `0.0.0.0:8765` so Codespaces port forwarding can reach it.

## Authentication

Every `POST /v1/analyze` request requires:

`Authorization: Bearer YOUR_CHESSHOOK_API_TOKEN`

The token is generated by `codespace.sh` and stored locally at `.secrets/api-token` (mode `0600`). The `.secrets/` directory is git-ignored and must never be committed. The token remains stable across normal Codespace stop/start cycles as long as the workspace is retained.

`GET /healthz` is intentionally unauthenticated and reports only engine readiness and configured resource values.

## Codespaces port access

Port `8765` is configured for automatic forwarding and is private by default. The Codespaces forwarded URL has the form:

`https://CODESPACE-NAME-8765.app.github.dev`

For external REST clients using a private forwarded port, GitHub requires an additional `X-Github-Token: $GITHUB_TOKEN` header. That Codespaces token changes when the Codespace is stopped and restarted. For direct phone-app use without a changing GitHub token, you can change port 8765 to **Public** in the Codespaces Ports panel; anyone can then reach the URL, but analysis requests still require the strong ChessHook bearer token. Keep the bearer token private.

## Health check

`GET /healthz`

Example response:

```json
{
  "ok": true,
  "engine": "Stockfish 19",
  "threads": 2,
  "hash_mb": 3584
}
```

The thread and hash values are examples. The installer detects the actual Codespace CPU and available memory at startup.

## Analyze a position

`POST /v1/analyze`

Headers:

- `Content-Type: application/json`
- `Authorization: Bearer YOUR_CHESSHOOK_API_TOKEN`

Request body:

| Field | Type | Default | Limits / meaning |
|---|---|---:|---|
| `fen` | string | — | Required. Six-field FEN, maximum 128 characters, exactly one king of each color. |
| `movetime_ms` | integer | `2000` | Clamped to 100–30000 milliseconds. |

Example request:

```bash
TOKEN="$(cat .secrets/api-token)"
curl -fsS -X POST 'http://localhost:8765/v1/analyze' \
  -H 'Content-Type: application/json' \
  -H "Authorization: Bearer $TOKEN" \
  -d '{"fen":"rnbqkbnr/pppppppp/8/8/8/8/PPPPPPPP/RNBQKBNR w KQkq - 0 1","movetime_ms":1000}'
```

Example success response:

```json
{
  "bestmove": "e2e4",
  "ponder": "e7e5",
  "depth": 18,
  "score_cp": 25,
  "score_mate": null,
  "nodes": 1234567,
  "nps": 1200000,
  "pv": ["e2e4", "e7e5", "g1f3"],
  "threads": 2,
  "hash_mb": 3584,
  "movetime_ms": 1000,
  "score_perspective": "side_to_move",
  "elapsed_ms": 1004
}
```

The values above are illustrative. Actual results depend on the position and Codespace load. `score_cp` is centipawns. When Stockfish reports a mate score, `score_mate` is populated and `score_cp` is null. The principal-variation moves in `pv` are UCI coordinate notation.

## Status codes

| HTTP status | Meaning |
|---|---|
| `200` | Analysis completed. |
| `400` | Invalid JSON, FEN, or request parameter. |
| `401` | Missing or incorrect ChessHook bearer token. |
| `404` | Unknown endpoint. |
| `413` | Missing or oversized request body (valid body size: 2–16384 bytes). |
| `429` | Another analysis is already running; retry shortly. |
| `503` | Engine or server-side configuration error. |

Only one search is run at a time because the service owns a single Stockfish process.
